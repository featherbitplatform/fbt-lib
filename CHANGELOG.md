# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.8.0] - 2026-11-14

### Added

- `fbt-core`: `text::display_safe(s, max_chars)` and `MAX_DISPLAY_CHARS` (256), both re-exported by `fbt`: remote text as a user should see it. Unicode control (Cc) and format (Cf) characters are dropped — a bidi override no longer makes a name that ends `.png` display as if it ended `.jpg`, zero-width characters hide nothing, a C1 control character does not move the cursor — combining marks with nothing to sit on are dropped, every run of whitespace becomes one space, the result is trimmed and cut to `max_chars` on a character boundary, so remote text can neither spoof a display nor allocate without bound. A cut never lands between two words, and what survives is otherwise exactly what came: no case change, no normalisation ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- `fbt-session`: `Settings::idle_status_interval` (default 5 s): a torrent that is seeding or paused with nothing going on — no peers, open readers, deadline pieces, web seeds in use, disk or hash jobs running, or piece layers to merge or re-read (a v2-only torrent whose layer fetch is still out is idle once its peers are gone: the fetch has no source until a peer arrives, and that event ends the idleness at once) — publishes its status snapshot (rates, `active_time`, `seeding_time`) and runs its seed-limit checks at this period instead of every `status_interval` (500 ms); LSD announces and the redial sweeps of a peerless torrent follow the same cadence. A command, a peer event or a job result switches back to `status_interval` at the end of the iteration that saw it, so nothing a user does waits for the slow tick; only continuously accumulating fields get coarser ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- `fbt-tracker`: `RedirectPolicy { allow_internal }`, re-exported by `fbt`, `#[non_exhaustive]` with `Default` allowing internal targets — which is how announces have always followed redirects. With `allow_internal` false a redirect target that is, or answers with, an address inside the local network (loopback, RFC 1918, IPv6 unique-local or link-local, CGNAT, the unspecified address, multicast or broadcast — one classifier, `fbt_net::addr::is_internal`, which folds IPv4-mapped, IPv4-compatibility, NAT64 and 6to4 spellings onto the IPv4 address they name) is refused before anything is sent to it, as the new `TrackerError::InternalRedirect`. What decides is the addresses the connection dials, not the text of the `Location` header; through a proxy that resolves names (`ProxyConfig::proxy_hostnames`) only a target spelled as an address is judged, because the proxy decides where a name goes ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- `fbt-session`: `TorrentStatus::layers_missing`, the BEP 52 piece layers the metadata does not hold yet (one per file of more than one piece whose layer is out; 0 for a v1 torrent and once every layer has arrived or been built), and the same field in `fbt-api`'s torrent model (`TorrentInfo`: `GET /api/v1/torrents`, a torrent's status, and the replies that add one) ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- `fbt-api`: `ApiConfig::stream_idle_timeout` (default 600 s): while a connection `ApiServer` serves still owes bytes to the client and the kernel has accepted none for that long, the client has stopped reading and the whole connection is ended — the file or event stream it was serving goes with it, freeing its `max_streams` or `max_event_streams` permit and its reader, and the client sees a short read. Progress means write progress: a client that keeps draining bytes, however slowly, is never cut off; an idle keep-alive connection owes nothing and stays open; a body merely waiting for pieces to write (a starved download) has nothing pending and is left alone. A stalled SSE stream is caught the same way as a stalled file. `Duration::ZERO` turns the guard off, and routers mounted outside `ApiServer` get none of it — whoever serves them owns its writers ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- `dev/stress.sh <package> <test-binary-or---lib> <test-name> <runs>` (Unix only): builds one test target through cargo's JSON and runs `<test-name>` `<runs>` times, 4 at a time (`STRESS_PARALLEL`), each repetition killed after `STRESS_TIMEOUT` seconds (default 600) together with everything it forked. It prints `stress: N/N passed`, exits non-zero on any failure, keeps every repetition's log in `target/stress/`, and treats a filter that matches no test as a failure rather than a pass ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- Interop: `expect_info <torrent> <expected line>` runs `fbt-example info` on a scenario's torrent, saves its whole output to the log directory CI uploads, and fails with that output inlined when the expected line is missing; `fail` now also copies the scenario `.torrent` files there, so a failed run leaves behind exactly what reproduces it ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))

### Changed

- Names written to disk change only for `.torrent` files whose names carry control or Unicode format characters: every path component drops those before the existing rules (illegal characters become `_`, reserved device names, no trailing dot or space, `MAX_COMPONENT_BYTES` with the extension kept), so a format or control character disappears instead of becoming `_` or spoofing what the name looks like, and a name cut by the byte rule keeps its extension (`…é.mkv` still ends `.mkv`) rather than losing its tail to the filter. Everything else survives exactly as the torrent gives it — whitespace included: repeated, leading and non-ASCII spaces are not collapsed or trimmed on disk (that collapse, `display_safe`, applies to displayed text), so `Artist  -  Title.flac` keeps its spacing. Torrent `name`, a magnet's `dn`, created torrents, renamed paths and resume paths inherit the rules; info hashes come from raw bytes and never change. Resume data written by 0.7.0 that names a file whose name now changes no longer matches its stamp, the check finds nothing under the new name, and such a file is re-downloaded once after upgrading (the copy left behind under the old name stays on disk for the user to remove) ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- A v2-only torrent starts before all of its piece layers arrive: `Event::MetadataReceived` and `TorrentStatus::has_metadata` now mean the metadata alone (they used to wait for the layers). `MetadataReceived` is no longer emitted at all for a `.torrent` added with its metadata, v2-only included — magnets emit it when the info dictionary arrives, before any layer — so an embedder that waited for it after adding such a `.torrent` would now wait forever. `DownloadingMetadata` is left to magnets still fetching their `.torrent`, and the download runs beside the layer fetch — pieces of a file whose layer is out are held back by the picker, its one-piece files download at once, and layers come from v2 peers in file order with the files readers ask for first. Data already on disk for a layer that lands late is found by reading it again, not fetched a second time, and only a file with wanted pieces holds `Seeding` back: a skipped file's layer is nobody's download. Hybrid torrents are unchanged ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- `fbt-tracker`: `TrackerClient::fetch_range` and `fetch_range_paced` take a `RedirectPolicy`. Breaking under 0.x for callers outside this workspace (nothing here called them except `fbt-session`, which passes `allow_internal` false when the seed's own address is public) ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- `fbt-api`: validation is stricter, with two new `ApiError` variants. `max_connections` must exceed `max_streams + max_event_streams` or the config is refused with `InvalidLimits` (breaking for configs that used to validate: every stream holder must leave room for a client that holds its connection without taking a stream, or the refusal an over-cap client gets could never be served); `router_with_shutdown` returns `NoRuntime` when called outside a Tokio runtime instead of panicking there ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))

### Fixed

- Remote strings that reach users are display-safe: tracker `failure reason` and `warning message`, web-seed error text, `.torrent` `name`, `comment` and `created by`, and peer client names (the session's own filter is replaced by the shared one and keeps its 64-character cap). Before, a bidi override or a zero-width character in any of them changed what a user saw, and a long one grew the message without bound ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- `fbt-session`: a web seed whose own address is public can no longer be redirected into the local network (loopback, RFC 1918, IPv6 unique-local and link-local, CGNAT, multicast). The target is judged on the addresses its connection dials — after resolution, so a name that answers inward between lookups is refused too, and a lookup that fails or times out ends the request rather than letting the target through — and the seed is retired with `Event::WebSeedError` without the target ever being asked. A torrent whose `url-list` already names a private address is a LAN seed and keeps working, its redirects included: what is guarded is where a public seed sends us, not where a seed lives. Through a proxy that resolves names (`ProxyConfig::proxy_hostnames`) nothing here is looked up locally: only a target spelled as an address is judged, because the proxy decides where a host name goes ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- `fbt-api`: a client that stops reading no longer holds a stream permit, a reader and a connection until the server restarts. `ApiServer` ends a connection whose owed bytes stop being written for `stream_idle_timeout`, which frees what the stalled file or event stream was holding; the caps are reached by live clients again. Routers mounted into somebody else's server get no stall protection — that server owns its writers, and only a hang-up frees the caps there ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- `fbt-api`: under `Auth::Disabled`, `ApiServer` refuses a peer that is not loopback with `403 forbidden`, so a token-less API bound to loopback cannot be reached through a redirector or a proxy on the same host. A router mounted without the connection's address keeps the `Host` and `Origin` guard alone, which is what its documentation says ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- `fbt-api`: an event stream delivers the events already queued before it ends on session shutdown; they used to be dropped with the queue ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
- Tests that failed now and then were reproduced with `dev/stress.sh` and fixed at their root cause; each cause and fix is written in the test's doc comment. Only one reproduced (the smart ban fixture, first bullet); the others were checks that could pass for the wrong reason or absence windows shorter than the 5 s floor: ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))
  - `honest_contributor_keeps_its_trust` (`fbt-session`, smart ban): with four one-piece files the leecher was finished the moment the disputed piece passed, so it went upload-only and closed the peer the test was watching (BEP 21), and that queued `PeerDisconnected { reason: UploadOnly }` was reported as "B was disconnected" — 3 failures in 100 runs at 36 copies, 9 in 300 loaded. The scenario now keeps a fifth one-piece file wanted by us and held by nobody, so the torrent is still downloading while the test asserts B stays connected
  - `rechoke_chokes_peer_that_lost_its_slot` (`fbt-session`, swarm): with the default 30 s `optimistic_unchoke_interval` nothing rotated inside the test, so its only `Choke` had to come from a peer that grabbed a free slot between rechokes and lost it, which needs three `Interested` messages processed inside 200 ms and a torrent still downloading when the choker ranks rates. Both intervals are now 1 s and the torrent is 8 MiB, so the asserted choke is a real optimistic rotation (the round-robin seeding choker that moved the slot is correct and pinned in `choker`'s own tests)
  - `simultaneous_dial_leaves_one_connection` (`fbt-session`, swarm): a fixed 3 s sleep then one status read — a snapshot published on a tick, after a dial that tries uTP first and TCP only after `utp_connect_timeout` — is replaced by waiting until both sides report exactly one peer, printing both counts when it does not happen
  - `router_with_shutdown_ends_open_events` (`fbt-api`): the suite's shortest budget (2 s) waited on a body hyper ends only when its task is next polled, and the stream was never shown to carry anything, so a slow start looked exactly like the failure under test. Liveness is proved first, then the wait runs at 5 s
  - `second_connection_from_one_ip_is_refused` (`fbt-session`, ipfilter) and `lost_skipped_piece_does_not_refinish` (`partfile`): absence windows of 1 s, 300 ms and 3 s are raised to 5 s, so a dial or a re-download that starts late on a loaded runner is seen instead of missed
  - `too_many_priorities_is_400` (`fbt-api`): replaced by a unit test that feeds the 4 194 304-priority cap through `serde_json::from_reader` over a generated endless array — microseconds and constant memory instead of a 25 MB body over a live session
  - `download_over_utp_from_seed_process` (`fbt-example`, CLI) and `ipv6_swarm_converges_when_available` (`fbt-dht`): did not reproduce in 100–300 runs, loaded included; their waits were reviewed (no fixed sleeps, budgets of at least 5 s) and the ephemeral-port race behind the first and why the convergence gate stays at "five known" for the second are recorded in their doc comments
- `fbt-session`: 1 000 idle seeding torrents cost about 0.2 % of a core instead of 1.70 %. The per-torrent status tick was the whole cost: an idle torrent republished a snapshot and re-ran its checks twice a second for nobody to read. Recorded rows for that column ran 0.82–1.70 in every release since it is recorded; the design spec's "under 1 % CPU" target is met on the benchmark host reliably (three consecutive runs) for the first time (see [docs/benchmarks.md](docs/benchmarks.md)) ([#23](https://github.com/featherbitplatform/fbt-lib/pull/23))

## [0.7.0] - 2026-11-13

### Added

- `fbt-api`: a new crate, an HTTP/JSON API over an `fbt::Session` built on axum (only this crate depends on a server stack; the core crates stay server-free). `router(session, &ApiConfig)` returns an `axum::Router` to mount in your own server, `router_with_shutdown` does the same and also ends open event and file streams when a future of yours completes (so your server's graceful shutdown does not wait on them), and `ApiServer::start` runs a standalone one. Route groups under `/api/v1`: ([#20](https://github.com/featherbitplatform/fbt-lib/pull/20))
  - torrents: list, status, `files`, `peers`, `trackers`, `pieces`, `resume-data` and `magnet`
  - control: add (`.torrent` upload or magnet), add from resume data, remove, pause, resume, recheck, reannounce, scrape, file priorities, per-torrent limits, queue position, auto-managed, move, rename file, web seeds and manual peers
  - session: settings and state, rate limits, queue settings, IP filter and banned peers
  - `create-torrent`: torrent creation with at most 2 creations at once
  - events: a server-sent event stream with category filters, a bounded subscriber queue and a `lagged` notice for a slow client
  - streaming: `GET` and `HEAD` of a torrent file with single `Range` requests (`206`, `416`, a `Range` the parser cannot serve falls back to a full `200`), fetching only what is read
  - `GET /api/v1/openapi.json`: the OpenAPI 3.1 document, served without a token and also available as `fbt_api::openapi()`
- `fbt-api` auth model: `Auth::Token` (bearer token on every request; `?token=` is accepted on the stream and event URLs only, for media elements and `EventSource`) or `Auth::Disabled`, which needs a loopback `bind` and answers `403` to a `Host` that is not `localhost`, `127.0.0.1` or `[::1]` and to an `Origin` not in `cors_origins` (the CSRF and DNS-rebinding guard); optional CORS origins ([#20](https://github.com/featherbitplatform/fbt-lib/pull/20))
- `fbt-api` limits: `allowed_roots` confines every path a request names (save paths, move targets, creation sources) to directories, with a lexical check before any filesystem access, symlinks resolved and refused when they leave the roots, `403 path_not_allowed` otherwise; request bodies capped (`MAX_BODY_BYTES`, 32 MiB by default, `413`), at most `max_streams` (32) file streams and `max_event_streams` (16) event streams at once (`503`), at most `max_connections` (256) connections served by `ApiServer` at once (further clients wait in the listen backlog), and a named cap on every collection a request carries (create-torrent tracker tiers, URLs and web seeds together at most 256, an empty tier counting as one; file priorities at most 4 194 304), enforced while the body is parsed; file streams are sent with `X-Content-Type-Options: nosniff` ([#20](https://github.com/featherbitplatform/fbt-lib/pull/20))
- `ApiServer::shutdown` is graceful and bounded: it stops accepting, ends event and file streams and aborts the remaining connections after a deadline ([#20](https://github.com/featherbitplatform/fbt-lib/pull/20))
- `fbt-session`: `TorrentHandle::files`, `peers` and `trackers` with the new `FileStatus`, `PeerStatus` and `TrackerStatus` types (re-exported by `fbt`) ([#20](https://github.com/featherbitplatform/fbt-lib/pull/20))
- `fbt-session`: `Session::rate_limit`, `peer_class_limits`, `queue_settings` and `is_shut_down`, the readers for what the session was configured with ([#20](https://github.com/featherbitplatform/fbt-lib/pull/20))
- `fbt-example`: `--api ADDR --api-token TOKEN` on `download` and `seed` serve the API next to the transfer (either flag alone is a usage error) ([#20](https://github.com/featherbitplatform/fbt-lib/pull/20))
- Fuzz target `http_range` (the `Range` header parser) with seeds ([#20](https://github.com/featherbitplatform/fbt-lib/pull/20))
- Interop scenario `api`: `fbt-example download --api` serves the API while it downloads, and curl lists the torrent, streams byte ranges, checks 401 and 416 and follows the event stream ([#20](https://github.com/featherbitplatform/fbt-lib/pull/20))

### Changed

- `PeerSource` gains the variants `Incoming`, `Manual`, `Resume` and `Holepunch`; match it with a wildcard arm. Redials of remembered peers keep the source they were learnt from, and the first source that learnt an address wins ([#20](https://github.com/featherbitplatform/fbt-lib/pull/20))
- Peer client names are sanitised: control and Unicode format characters are stripped and a name is at most 64 characters. The libtorrent Azureus ids are corrected (`LT` is "libtorrent", `lt` is "libTorrent") ([#20](https://github.com/featherbitplatform/fbt-lib/pull/20))

## [0.6.0] - 2026-11-13

### Added

- BitTorrent v2 and hybrid torrents (BEP 52): `fbt-core` gains Merkle trees (`merkle` module: `MerkleTree`, `piece_root`, `layer_root`, `leaf_hashes`, `file_tree_height`, `verify_hashes`); `fbt-metainfo` parses v2-only and hybrid `.torrent` files with their piece layers (`Metainfo::version`, `TorrentVersion`, `Metainfo::v2_piece`, `V2Piece`, `Metainfo::with_piece_layers`, `validate_layer`, `MetainfoError::InconsistentHybrid`, `MAX_PIECE_LAYER_HASHES`, `MAX_V2_PIECES`); a hybrid is checked for consistency between its halves; `fbt-session` verifies pieces by SHA-1, by Merkle root or by both, and builds the piece layers a hybrid lacks while it downloads ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `fbt-metainfo`: torrent creation: `CreateTorrent` (`new`, `version`, `piece_len`, `trackers`, `web_seeds`, `comment`, `created_by`, `creation_date`, `private`, `build` with a progress callback that can cancel), `CreateError`, `auto_piece_len` and `MAX_CREATE_FILES`, for v1, v2 and hybrid torrents; re-exported by `fbt`, with a creation doctest ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `fbt-wire`: the BEP 52 messages `HashRequest`, `Hashes` and `HashReject` (`MAX_HASH_REQUEST_LEN`) and `Reserved::supports_v2` and `Reserved::set_v2` ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `fbt-session`: a torrent is registered under every wire hash (a hybrid under both its v1 and truncated v2 hash) and a `btmh`-only (v2) magnet is accepted; `Session::torrent` also finds a torrent by any of its wire hashes ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `fbt-session`: hash serving: a seed answers hash requests from its piece layers (Merkle trees cached, serving jobs and pending requests capped); a v2-only torrent whose `.torrent` or magnet metadata lacks piece layers fetches them from v2 peers over hash requests, verified against each file's `pieces root` ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `fbt-session`: a hybrid torrent announces under both its info hashes: every tracker, the DHT and LSD run once per hash ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `fbt-session`: resume data version 2 stores v2 info hashes and piece layers (see Changed) ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `fbt-example`: `create PATH --out FILE [--format v1|v2|hybrid] [--piece-size BYTES] [--tracker URL] [--web-seed URL] [--private] [--comment TEXT]` ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- Fuzz target `hash_proof` (Merkle proof verification and hash messages), with seed corpora for the new wire messages ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- Interop scenarios `v2` and `hybrid` against qBittorrent-nox and Transmission: created torrents give the same hashes as qBittorrent's creator, v2 downloads and seeds both ways, a `btmh` magnet fetches its layers over hash requests ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))

### Changed

- `SessionError::V2OnlyUnsupported` is deprecated and no longer produced: v2 (`btmh`-only) magnets are accepted, `Session::torrent()` also finds a torrent by any of its wire hashes and a hybrid is registered under both hashes ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `MetainfoError::V2OnlyUnsupported` is deprecated and no longer produced ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `FileEntry` gains `pieces_root` (breaking for struct literals), `Metainfo::piece_layers` is new, and `Info.pieces` is empty for a v2-only torrent ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- The v2 reserved bit is set on the handshakes of torrents that have a v2 hash, and a connection made under a truncated v2 hash counts as v2 ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- A v2-only `.torrent` without piece layers starts in `DownloadingMetadata` (`has_metadata` false, `metainfo()` `None`) until its layers are fetched ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `Event::TrackerReply` gains `info_hash`, the hash the announce was made under (breaking for struct patterns without `..`); hybrids announce under both hashes ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `fbt_session::storage::check_pieces` has a new signature: it takes the `Metainfo` and also returns the v2 roots of the pieces that passed ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- Resume data is version 2, which older builds cannot read: `info-hash` is optional, and the new keys are `info-hash2` and `piece-layers`; version 1 is still read ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `fbt_wire::Message` gains three variants (`HashRequest`, `Hashes`, `HashReject`); match with a wildcard arm ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `fbt-example info` prints the wire hash (40 hex), `info hash v2:` when there is one, and `version:` ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- Created multi-file hybrids carry a tail pad after their last file, so their hashes match libtorrent 2.0 and qBittorrent 5.3 exactly (a single-file hybrid has no file list to hold one) ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `ResumeError::InfoHashMismatch` reads "the resume data's torrent does not match its info hash": it now covers `info-hash2` too ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- A v2 file tree is single-file only when its one top-level entry is a file whose key equals `name`; any other tree is a directory named `name` ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))
- `fbt-metainfo`: a torrent without v1 `pieces` (v2-only) is refused with `MetainfoError::InvalidField` (`length`, "too many pieces") when it has more than `MAX_V2_PIECES` (4,194,304, equal to `MAX_PIECE_LAYER_HASHES`) pieces, both from a `.torrent` and from metadata fetched for a `btmh` magnet; `CreateTorrent::build` refuses such a v2-only torrent with the new `CreateError::TooManyPieces`. Before, a 154-byte v2 `.torrent` could claim 2^32 - 1 pieces and abort the process when the session sized its per-piece state ([#17](https://github.com/featherbitplatform/fbt-lib/pull/17))

## [0.5.0] - 2026-11-13

### Added

- `fbt-session`: resume data: the async `TorrentHandle::save_resume_data` returns a torrent's state as bytes (its `info` dictionary, save path, priorities, renamed files, verified pieces, web seeds, queue position, counters, times, up to `MAX_RESUME_PEERS` peers per family and a `FileStamp` per file and for the part file), and `AddTorrent::from_resume` turns it back into add parameters; the saved pieces are trusted without a check when every file holding one has the length and modification time it had at the save, else the torrent is checked in full; hostile resume data fails with `ResumeError` (`MAX_RESUME_BYTES`, `MAX_RESUME_ITEMS`) ([#14](https://github.com/featherbitplatform/fbt-lib/pull/14))
- `fbt-session`: session state: `SessionState` (`to_bytes`, `from_bytes`, at most `MAX_SESSION_TORRENTS` torrents) with the async `Session::save_state` and `Session::shutdown_and_save`, which return the DHT state and every torrent's resume data in queue order plus the torrents they could not save with their error, and the async `Session::restore`, which starts a session from it and returns the torrents it could not add ([#14](https://github.com/featherbitplatform/fbt-lib/pull/14))
- `fbt-session`: `Storage::stamps` and `FileStamp` (with `FileStamp::new` for custom storages); a custom `Storage` without stamps is trusted ([#14](https://github.com/featherbitplatform/fbt-lib/pull/14))
- `fbt-session`: auto-managed queueing as libtorrent's: `QueueSettings` (`active_downloads` 3, `active_seeds` 5, `active_limit` 500, `dont_count_slow_torrents` with `inactive_down_rate`, `inactive_up_rate` and `startup_grace`, and `interval`), `Settings::queue`, `Session::set_queue_settings`, `AddTorrent::auto_managed`, and the async `TorrentHandle::set_auto_managed` and `TorrentHandle::set_queue_position`; a torrent the user paused is never started by the queue ([#14](https://github.com/featherbitplatform/fbt-lib/pull/14))

- Incoming handshakes in progress are capped per source IP, and a duplicate connection is suppressed by a deterministic tie-break ([#8](https://github.com/featherbitplatform/fbt-lib/pull/8))
- `fbt-net` `natpmp`: `Mapping` carries the PCP nonce and the gateway epoch, and `renew` and `unmap` take the previous mapping ([#8](https://github.com/featherbitplatform/fbt-lib/pull/8))

### Fixed

- `fbt-session`: the first retry of a failed outgoing connection now comes after 5 s (a twelfth of the retry delay) instead of a full minute, so a peer that was not ready yet (starting, checking its files, briefly full) no longer stalls a download that has no other peer ([#7](https://github.com/featherbitplatform/fbt-lib/pull/7))
- `fbt-session`: upload is no longer counted for blocks the peer cancelled ([#8](https://github.com/featherbitplatform/fbt-lib/pull/8))
- `fbt-wire`: MSE drain errors are surfaced instead of swallowed ([#8](https://github.com/featherbitplatform/fbt-lib/pull/8))
- `fbt-session`: file-handle eviction no longer syncs the file on every eviction ([#8](https://github.com/featherbitplatform/fbt-lib/pull/8))
- `fbt-dht`: bootstrap attempts are spaced from their start, and a bootstrap whose attempt dies is rescheduled ([#8](https://github.com/featherbitplatform/fbt-lib/pull/8))
- `fbt-session`: metadata pieces already received are kept when their source is retired ([#8](https://github.com/featherbitplatform/fbt-lib/pull/8))
- `fbt-session`: PEX no longer rebuilds its peer list on every tick ([#8](https://github.com/featherbitplatform/fbt-lib/pull/8))
- `fbt-utp`: an incoming connection reaches `UtpSocket::accept` only once the dialler acks our handshake, and at most `UtpConfig::max_pending_accept` connections are half-open (the oldest is dropped for a newer SYN), so a flood of forged SYNs no longer takes the session's pending-handshake slots or fills the uTP connection table ([#8](https://github.com/featherbitplatform/fbt-lib/pull/8))
- `fbt-net`: a UPnP renewal asks for the external port it holds, so a mapping moved to a random port after a conflict is no longer leaked on the router at each renewal ([#8](https://github.com/featherbitplatform/fbt-lib/pull/8))
- `fbt-utp`: a selective ack of any non-empty length is accepted. libtorrent (qBittorrent) sends only the bytes its bits need rather than a multiple of four, and such packets, data included, were dropped whole: transfers from libtorrent stalled for an RTO whenever it had a hole in our stream, and deadlocked once a lost packet of ours left every one of its packets carrying a SACK ([#8](https://github.com/featherbitplatform/fbt-lib/pull/8))
- `fbt-session`: an outgoing peer that traded data and then went away (closed, timed out or idle) is dialled again after the first retry delay (5 s by default) instead of only when a tracker or PEX names it again ([#8](https://github.com/featherbitplatform/fbt-lib/pull/8))

- `fbt-session`: `Settings::encryption` (`EncryptionPolicy`: `Forced`, `Preferred`, `Disabled`) for MSE/PE on outgoing and incoming connections, and `DisconnectReason::Encryption` for a failed MSE handshake ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- `fbt-session`: `Session::dht_stats()` returning `DhtStats`, and `Settings::dht_ipv6`, `Settings::dht_read_only` and `Settings::dht_announce_interval` ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- `fbt-session`: `Event::PeersFound` (with its `PeerSource`), `TorrentStatus::has_metadata` and `TorrentHandle::metainfo()` ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- `fbt-session`: `SessionError::NoMetadata` (a command that needs the metadata of a magnet still fetching it) and `SessionError::V2OnlyUnsupported` ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))

### Changed

- `AddTorrent.metainfo` is now `AddTorrent.source: TorrentSource`; `AddTorrent::new` still takes a `Metainfo`. Breaking under 0.x ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- `fbt-bencode`: `Limits` gained a field (`max_items`), so struct-literal construction no longer compiles; use `Limits::new` ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- `Settings::default()` now has encryption `Preferred`: outgoing connections open with an MSE handshake and fall back to plain text only where the policy allows it ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- `TorrentState` and `Event` gained variants (`DownloadingMetadata`, `MetadataReceived`, `DhtBootstrapped`); match with a wildcard arm ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- When two peers dial each other at once, the connection initiated by the lower peer id is kept ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- `Settings::default()` now starts a DHT node and contacts the public routers (`DEFAULT_DHT_BOOTSTRAP`); set `dht_enabled = false` to stay off the DHT ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))

### Fixed

- `fbt-session`: the `completed` tracker announce is sent at most once, and is retried after a failed attempt ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- `fbt-session`: the `left` value of a `stopped` announce after a recheck is the last known one ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- `fbt-session`: a magnet answers incoming peers during the check that follows its metadata instead of dropping them ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- `fbt-session`: a torrent whose check after the metadata fails stops like any errored torrent: it announces `stopped`, refuses incoming peers, and a resume starts over cleanly ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- `fbt-session`: a slow metadata source can no longer stall a magnet: each request times out on its own, and a source that has not delivered the whole metadata within its deadline gives its slot to the next one ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))
- `fbt-session`: the status read on `TorrentFinished` already has the final counters and the `Seeding` state, instead of the last periodic snapshot ([#4](https://github.com/featherbitplatform/fbt-lib/pull/4))

## [0.1.0] - 2026-11-10

### Added

- `fbt-bencode`: bencode decoder and encoder with strict canonical-form checks, bounded depth and exact-span access for info-hash computation ([#1](https://github.com/featherbitplatform/fbt-lib/pull/1))
- `fbt-core`: info hashes (v1, v2 and hybrid), peer ids (`-FB0100-` prefix), bitfields, piece and file layouts, block references ([#1](https://github.com/featherbitplatform/fbt-lib/pull/1))
- `fbt-metainfo`: `.torrent` parsing for v1 and hybrid torrents (v2-only from milestone 6), with hostile-input limits (at most 64 tracker URLs) and path sanitising (Windows device names included) ([#1](https://github.com/featherbitplatform/fbt-lib/pull/1))
- `fbt-wire`: peer wire protocol codec (handshake and messages) with bounded frame sizes ([#1](https://github.com/featherbitplatform/fbt-lib/pull/1))
- `fbt-tracker`: HTTP(S) and UDP tracker announces over rustls, with tracker-supplied text cut to 1 KiB, time-bounded UDP host lookups and an IPv4/IPv6 fallback; `TrackerConfig` is `#[non_exhaustive]` ([#1](https://github.com/featherbitplatform/fbt-lib/pull/1))
- `fbt-session`: async session on tokio with torrent management, piece picking, verified storage (`FsStorage`, `MemStorage`), peer connections, tracker announces and an event stream; `Session::new` validates its `Settings` (`SessionError::InvalidSettings`), duplicate peer ids are refused (`DisconnectReason::Duplicate`), and remove and shutdown cancel a running piece check ([#1](https://github.com/featherbitplatform/fbt-lib/pull/1))
- `fbt`: public facade crate re-exporting the stable API ([#1](https://github.com/featherbitplatform/fbt-lib/pull/1))
- `fbt-example`: command-line downloader and seeder built on the facade ([#1](https://github.com/featherbitplatform/fbt-lib/pull/1))
- Features `tls` (default, rustls with `ring`) and `pure-rust` (rustls with the RustCrypto provider, no C or assembly), with a `dev/check-pure-rust.sh` guard ([#1](https://github.com/featherbitplatform/fbt-lib/pull/1))
- Fuzz targets for bencode, metainfo, the wire codec, handshake, HTTP and UDP announce parsing and path handling, with seed corpora and a fuzz workflow ([#1](https://github.com/featherbitplatform/fbt-lib/pull/1))
- Interop tests against qBittorrent-nox and Transmission through opentracker (`dev/interop/run.sh`, run in CI) ([#1](https://github.com/featherbitplatform/fbt-lib/pull/1))
