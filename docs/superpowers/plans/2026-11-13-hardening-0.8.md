# Hardening Release 0.8.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `fbt-lib` `v0.8.0`, a release that adds no features. It does six things:
- meets the spec's idle-CPU target;
- removes the known flaky tests;
- makes interop failures diagnosable;
- strips spoofing characters from every remote string shown to users;
- closes the web-seed and API hardening gaps found in milestones 5 to 7;
- fetches v2 piece layers lazily, as libtorrent does.

**Architecture:** Each task is self-contained and touches one subsystem:
- the actor's status tick;
- the test suites;
- `dev/interop`;
- a shared sanitiser in `fbt-core`;
- the web-seed client;
- `fbt-api`;
- the layer fetch.

No public API is removed. Additions are `#[non_exhaustive]`-safe.

**Tech Stack:** as milestone 7. No new crates.

**Spec:** `docs/superpowers/specs/2026-11-10-fbt-lib-design.md` (binding). Inputs:
- section 7: "1,000 idle seeding torrents stay under 1% CPU";
- section 3 anti-goal: "Any panic, hang or unbounded memory growth triggered by remote input";
- section 2 goal 5: safe against hostile peers, trackers and DHT nodes;
- section 5.6: `fbt-api` security model;
- the "Deferred" and "Backlog" sections of the milestone 5, 6 and 7 plans, and the backlogs in the bodies of PR #17 and PR #20.

The owner asked for this hardening step on 2026-11-13 ("lets do some hardening").

## Global Constraints

- **No unsafe.** `#![forbid(unsafe_code)]` stays in every crate.
- **No BitTorrent crates.**
- **`pure-rust` and the server-free core.**
  - `bash dev/check-pure-rust.sh` passes after every task that touches a `Cargo.toml`.
  - Only `fbt-api` may pull in server crates.
- **Remote input never panics, hangs or allocates without bound.**
  - The clippy deny block (`unwrap_used`, `expect_used`, `indexing_slicing`, `panic` outside tests) stays where it is, and is added to any new module of a crate that has it.
  - Every new collection has a named cap.
- **Tests never contact the public internet,** and the interop networks stay `internal: true`.
- **Cross-platform.** macOS, Linux and Windows all pass.
  - Code compiled only on one OS leaves no unused imports on the others.
  - Timing-based tests use bounded waits of at least 5 s.
- **No index loops**, because CI's stable clippy flags `needless_range_loop`.
- **Commits.** Conventional Commits with the crate as scope.
- **No attribution of any kind in commits or PRs:** no `Co-Authored-By`, no `Claude-Session`, no session links, no "Generated with" footer.
- **Toolchain and crate settings.** Edition 2024, `rust-version = "1.99"`, `publish = false`, Apache-2.0.
- **Logging and errors.** `tracing` for logs, `thiserror` for errors.
- **Public API changes.** Every new public type or item is re-exported where its crate's other types are (`fbt`, `fbt-api`) and pinned in that crate's `tests/lib_surface.rs`. Breaking changes go under `### Changed` in `CHANGELOG.md`.
- **Local builds.** Use `CARGO_INCREMENTAL=0`.

## Review Focus

1. **An idle torrent that is not idle.**
   - Inputs:
     - a torrent with a reader open;
     - a torrent that is checking, moving storage or fetching layers;
     - a torrent with a deadline piece;
     - a torrent whose peer connects while it is in the slow tick.
   - Expected: the slow tick applies only to torrents that are seeding or paused, with no peers, readers, deadlines, web seeds, jobs or pending layers. Any event that ends idleness switches back to the normal tick at once; status, readers and tests never wait for the slow interval.
   - Tests: Task 1 `idle_torrent_uses_the_slow_tick`, `peer_arrival_restores_the_fast_tick`, `reader_keeps_the_fast_tick`.
2. **Strings that spoof.**
   - Inputs: a torrent name, file path, comment, `created by`, tracker failure reason, web-seed error, peer client or DHT version string containing:
     - bidi overrides (`U+202E`);
     - zero-width characters;
     - BOM;
     - C0 and C1 controls;
     - lone combining marks;
     - 10 000 characters.
   - Expected:
     - Every string that reaches `TorrentStatus`, events, detail calls or file names on disk has format and control characters removed and is length-capped.
     - A file name whose extension a bidi override would have reversed (`exe‮gpj.`) is written to disk as the plain `exegpj.`.
     - Info hashes are unchanged.
   - Tests: Task 4 `display_safe_table`, `spoofed_extension_is_flattened_on_disk`, `tracker_failure_reason_is_display_safe`, `metainfo_strings_are_display_safe`.
3. **A web seed that points inward.**
   - Inputs:
     - a public web-seed URL that redirects to `http://127.0.0.1:…`, `http://192.168.1.1`, `http://[::1]` or `http://169.254.169.254`;
     - a host name that resolves to a private address;
     - a `url-list` entry that is private to begin with.
   - Expected:
     - A redirect from a public origin to a loopback, private, link-local or unspecified address is refused, and the seed is retired with `WebSeedError`.
     - Seeds configured on a private address keep working: a LAN seed is legitimate.
     - The check uses the resolved addresses, not the URL text.
   - Tests: Task 5 `redirect_to_loopback_is_refused`, `hostname_resolving_private_is_refused_after_redirect`, `private_seed_still_works`.
4. **API clients that hold resources.**
   - Inputs:
     - a stream or SSE client that stops reading but keeps the connection open;
     - `max_connections` at or below `max_streams + max_event_streams`;
     - `router_with_shutdown` called outside a runtime;
     - under `Auth::Disabled`, a non-loopback peer that sends `Host: localhost`.
   - Expected:
     - A body not polled for `stream_idle_timeout` (default 10 min) ends and frees its permit and reader.
     - The config is refused with `ApiError::InvalidLimits`.
     - `router_with_shutdown` returns `Err(ApiError::NoRuntime)` instead of panicking.
     - `ApiServer` refuses the non-loopback peer with 403.
   - Tests: Task 6 `stalled_stream_is_ended`, `stalled_sse_is_ended`, `connection_cap_must_exceed_stream_caps`, `router_with_shutdown_outside_runtime_errors`, `disabled_auth_refuses_remote_peer`.
5. **Lazy layer fetch under churn.**
   - Inputs:
     - a v2 magnet whose only v2 peer leaves after metadata;
     - pieces of a one-piece file wanted before any layer arrives;
     - a reader on a file whose layer is missing;
     - pause and resume mid-fetch;
     - a layer that fails its proof.
   - Expected:
     - One-piece files download at once.
     - Multi-piece files are picked only after their layer arrives.
     - A reader on such a file waits; it does not fail.
     - Bad proofs retire the source.
     - The torrent finishes once a v2 peer returns.
   - Tests: Task 7 `one_piece_files_download_before_layers`, `reader_waits_for_its_layer`, `fetch_survives_source_churn`.

## Decisions recorded in this plan

The owner chose this hardening release over starting featherbittorrent or 1.0.0 (2026-11-13). The builder made these calls:

- **Idle CPU.** The spec's target is under 1% CPU for 1,000 idle seeding torrents. Recorded runs measured 1.18, 1.13, 1.15, 1.55, 0.82 and 1.70, so the target has never been met reliably, and 0.7.0 is not a regression.
  - The fix is the milestone 4 backlog item: an adaptive status tick.
  - An idle torrent ticks every `idle_status_interval` (new `Settings` field, default 5 s) instead of every `status_interval` (1 s).
  - "Idle" is exactly the set listed in Review Focus 1.
  - Leaving idle is immediate: the actor resets its interval on the triggering event.
  - Accepted result: `dev/bench.sh` idle CPU below 1.0 in 3 consecutive runs on the dev machine. Record all three in the task report; the release row records one.
- **Flaky tests.** Each known flake gets a root cause and a fix, never a longer timeout alone. The cause and the fix are recorded in the test's doc comment. The flakes:
  - `rechoke_chokes_peer_that_lost_its_slot` (`crates/fbt-session/tests/swarm.rs`)
  - `simultaneous_dial_leaves_one_connection` (`swarm.rs`)
  - `honest_contributor_keeps_its_trust` (`tests/smartban.rs`)
  - `second_connection_from_one_ip_is_refused` (`tests/ipfilter.rs`)
  - `lost_skipped_piece_does_not_refinish` (`tests/partfile.rs`)
  - `download_over_utp_from_seed_process` (`crates/fbt-example/tests/cli.rs`)
  - `router_with_shutdown_ends_open_events` (`crates/fbt-api/tests/events.rs`, 2 s budget)

  Also make `too_many_priorities_is_400` cheap: test the cap at the unit level, and keep the HTTP test with a cap lowered by a test-only config, or drop it in favour of the unit test.
  - Acceptance: each flake passes 100 consecutive runs under load (a stress script, `dev/stress.sh <crate> <test> <n>`, running 4 copies in parallel).
- **Interop diagnostics.**
  - `fail` in `dev/interop/run.sh` copies every `/interop/*.torrent` and every `fbt-example info` output it has into `target/interop/logs/`.
  - Each `fbt fbt-example info … | grep …` check is replaced by a helper, `expect_info <torrent> <line>`, that saves the full output and prints it on failure.
- **`display_safe`.**
  - Signature: `fbt_core::text::display_safe(s: &str, max_chars: usize) -> String`.
  - It drops Unicode Cc and Cf characters (Task 2 of milestone 7 already has a hand-written Cf table in `crates/fbt-session/src/peer.rs`, which moves here). It drops combining marks that have no base, collapses runs of whitespace to one space, trims, and truncates at a character boundary.
  - The constant is `MAX_DISPLAY_CHARS` = 256 for messages and names.
  - Applied to:
    - metainfo `name`, path components, `comment` and `created by` (paths: in `sanitize_component`, so on-disk names are flattened too);
    - tracker `failure reason` and `warning message`;
    - web-seed error text;
    - peer client names (replacing `sanitise_client`, which keeps its 64-character cap);
    - DHT `v` strings where they are exposed.
  - Paths keep their existing rules as well (reserved names, length per component).
  - Info hashes are computed from raw bytes, so they never change. Resume data written by 0.7.0 that names a file whose name changes is caught by the stamp check and rechecked. This is documented under `### Changed`.
- **Web-seed redirect guard.**
  - A seed whose configured host resolves to a public address may not be redirected to a host that resolves to a loopback, private (RFC 1918, ULA `fc00::/7`), link-local, CGNAT (`100.64/10`), unspecified, multicast or broadcast address.
  - The check runs on every address the connector resolves for the redirect target, so a public name that resolves to a private address is refused too.
  - A seed whose first URL is already private is a LAN seed and may stay private.
  - The classifier is one function: `fbt_net::addr::is_internal(ip: IpAddr) -> bool`.
  - A refusal retires the seed with `WebSeedError`.
- **API hardening (`fbt-api`).**
  - `ApiConfig::stream_idle_timeout: Duration`, default 10 min.
    - A file-stream or SSE body that hyper has not polled for that long ends.
    - A watchdog timer resets on every poll and is checked from the body's own `poll_next` plus a timer.
    - SSE keep-alive comments count as polls.
  - `ApiConfig` validation also requires `max_connections > max_streams + max_event_streams`, else `ApiError::InvalidLimits`.
  - `router_with_shutdown` uses `tokio::runtime::Handle::try_current()` and returns `Err(ApiError::NoRuntime)` outside a runtime.
  - `ApiServer` attaches `ConnectInfo<SocketAddr>`. Under `Auth::Disabled` the auth layer refuses a non-loopback peer with 403 `forbidden` when that extension is present; mounted routers without it keep the Host/Origin guard, which is documented.
  - SSE drains the events already queued before it ends on session shutdown.
- **Lazy v2 layer fetch (milestone 6 backlog).**
  - A v2-only torrent no longer waits in `DownloadingMetadata` for every layer. It starts as soon as its metadata is known.
  - **Picking.** Pieces of files without a layer are not pickable until the layer arrives, through a picker filter, not by changing priorities. One-piece files never need a layer, and the part file and priorities are unaffected.
  - **Fetching.** `LayerFetch` keeps running beside the download, fetching layers in file order, and the files readers ask for first.
  - **Swaps.** Each arriving layer is merged with `with_piece_layers`, batched at most once a second.
  - **Status.** `has_metadata` becomes true as soon as the metadata is installed. `TorrentStatus` gains `layers_missing: u32`.
  - **Readers.** A reader on a file without a layer waits, as for a missing piece.
- **Out of scope** (left in the backlog):
  - the BEP 44 per-IP quota;
  - refunding upload reservations;
  - SOCKS5 UDP extras;
  - IP-filter file parsers;
  - block-layer hash requests;
  - multi-threaded creation;
  - `TrackerError` gaining a hash;
  - the efficiency minors of milestone 6 (double validation, `Metainfo` clone per swap).
- **Version and changelog.** Version `0.8.0`; changelog entries go under `## [Unreleased]`.

### Task 6: `fbt-api` hardening

**Files:**
- Create: `crates/fbt-api/src/watchdog.rs`
